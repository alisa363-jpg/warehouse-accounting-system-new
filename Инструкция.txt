ЗАПУСК

Требуются Windows и .NET SDK 10. На этом компьютере SDK уже установлен.
Запуск из терминала в папке проекта:
dotnet run --project Warehouse.csproj -- .

При запуске выберите рабочее место одной из пяти крупных кнопок.
Это выбор роли без пароля. В рабочем окне видны только её разделы:
— менеджер по заказам: клиенты и заказы;
— менеджер по закупкам: поставщики, закупки и потребность;
— кладовщик: товары, категории, заказы и закупки для сверки поставок,
  спецификации и отгрузки, остатки и приёмки;
— бухгалтер: заказы и закупки для счетов, оплат и накладных, платежи и отчёты;
— курьер: доставка заказов со статусами «Передан доставке», «В пути»
  и «Расхождение». Завершённые доставки в этом списке не показываются.
Кнопка «← Сменить роль» закрывает рабочее окно и возвращает к выбору.
Сохранённые данные и папка склада остаются общими для всех ролей.
Закрытие окна крестиком завершает приложение.

При первом запуске база пустая.
Кнопка «Заполнить пример» создаёт две позиции, дерево категорий,
поставщика и клиента. Она работает только с пустыми справочниками.
Поставки и заказы оформляются самостоятельно по сценарию ниже.

Данные сохраняются в data.json в папке, переданной программе.
Точка в команде означает текущую папку. Без аргумента используется папка exe.
data.lock — служебный файл блокировки; его наличие не означает,
что база занята. Блокировкой служит открытый файловый дескриптор.
bin и obj создаются автоматически при сборке, вручную их писать не нужно.

КАК УСТРОЕН КОД

Warehouse.csproj — настройки C# и Windows Forms, внешних пакетов нет.
Models.cs — обычные классы данных и списки: товары, категории,
контрагенты, документы, строки, платежи, партии и движения.
Storage.cs — загрузка и сохранение JSON, проверка версии данных.
WarehouseService.cs — правила и операции склада.
Program.cs — запуск, главное окно и диалоги ввода.
RoleSelectionForm.cs — окно выбора рабочего места с пятью кнопками.
Documents.cs — запись документов Word и таблиц Excel.

Архитектура состоит из трёх слоёв: интерфейс, бизнес-логика, хранение.
Например, кнопка «Отгрузить» вызывает WarehouseService.Ship.
Метод проверяет оплату, накладную и количество, уменьшает остатки,
записывает движения и меняет состояние. Storage сохраняет результат.
Окно не изменяет остатки самостоятельно.
Отдельные интерфейсы, контейнеры зависимостей и сервер не добавлены:
для одного способа хранения в учебном проекте они не нужны.

Order используется для двух сходных документов. Purchase=true означает
закупку, false — заказ клиента. Они хранятся как разные записи с общим
сквозным номером; платежи и движения ссылаются на этот номер.
Line — строка документа. Quantity — заказано, Received — сверено и принято
кладовщиком, включая позиции, ещё ожидающие накладную.
Receipt — результат сверки одной позиции: количество, дата, срок годности
и кладовщик. WaybillNumber=0 означает ожидание оформления бухгалтером.
Эти записи хранятся в Order.Receipts и видны во вкладке «Приёмки».
Batch — отдельная поставленная партия. Movement — факт прихода/расхода.
Receive сохраняет результат сверки, но не добавляет партии в остатки.
MakeDocument при оформлении приходной накладной присваивает номер
ожидающим позициям и затем добавляет партии и движения в одной операции.
Повторное открытие оформленной накладной не создаёт повторного прихода.
Цены строк фиксируются при оформлении документа. Цена партии берётся
из закупки; именно по ней рассчитывается стоимость наличного склада.
Сумма заказа — сумма Quantity * Price по всем его строкам.

ЧТО ПОКАЗАТЬ НА ЭТАПЕ 2

1. Объяснить назначение файлов C# и вызов окно → сервис → хранилище.
2. Создать товар, клиента и поставщика.
3. Создать закупку, сверить товар кладовщиком, затем оформить приходную
   накладную бухгалтером и показать появившиеся остатки.
4. Создать заказ и показать отказ отгрузки до полной оплаты.
5. Оплатить и отгрузить заказ, показать уменьшение остатка.
6. Перезапустить приложение и показать сохранённые данные.
7. Открыть локальный Git-репозиторий и историю изменений.

ЧТО ПОКАЗАТЬ НА ЭТАПЕ 3

Те же функции плюс дерево категорий, реквизиты контрагентов, поиск,

Один проект содержит оба этапа; это не две отдельные программы.

ПРИМЕР ПОЛНОГО СЦЕНАРИЯ

Для каждого следующего рабочего места используйте «← Сменить роль».

1. Выбрать «Кладовщик» и нажать «Заполнить пример».
2. Выбрать роль «Менеджер по закупкам». Во вкладке «Закупки»
   нажать «Новая закупка». Выбрать ООО Поставка. В пустой строке таблицы
   выбрать бумагу, указать количество 10 и цену 10. Сохранить.
3. Выбрать «Бухгалтер». Выделить закупку. Нажать «Счёт», затем «Оплата»
   и указать 100. Пока поставка не сверена, приходную накладную оформить
   нельзя. Оплата поставщику сама по себе не изменяет остатки.
4. Выбрать «Кладовщик», нажать «Сверить поставку». Код бумаги — 1.
   Проверить фактическую поставку и ввести 4 принятые единицы.
   Для бумаги срок годности оставить пустым, указать кладовщика.
   Состояние — «Ожидает приходную накладную». Во вкладке «Приёмки» есть
   4 единицы, но во вкладке «Остатки» их ещё нет.
   Выбрать «Бухгалтер», выделить закупку и нажать «Накладная».
   Проверить показанные позиции и подтвердить оформление: документ
   содержит 4 единицы на сумму 40, после чего они приходуются.
   Состояние станет «Получен частично». Сохранить файл в Word или Excel.
   Затем кладовщик сверяет оставшиеся 6 единиц, бухгалтер оформляет
   следующую накладную на 6 единиц и сумму 60. Состояние — «Получен».
   Во вкладке «Остатки» будут две отдельные партии, всего 10 единиц.
5. Выбрать «Менеджер по заказам». Создать заказ ООО Покупатель:
   бумага, количество 3, цена 15. Итого 45.
   «Состав / изменить» позволяет изменить или удалить строки до отгрузки.
   Для удаления выделить всю строку слева и нажать Delete.
6. Выбрать «Кладовщик», попробовать отгрузить: появится отказ.
7. Выбрать «Бухгалтер», оформить счёт и зарегистрировать оплату 20.
   Попытка оформления расходной накладной будет отклонена.
   Зарегистрировать ещё 25, оформить расходную накладную.
8. Выбрать «Кладовщик», сохранить спецификацию. Проверить физическую
   комплектацию партии и нажать «Отгрузить». Подтвердить передачу.
   На складе останется 7 единиц бумаги стоимостью 70.
   Повторная отгрузка того же заказа будет отклонена.
9. Выбрать «Курьер», нажать «Доставка». Результат «Принята» переводит
   заказ в состояние «В пути». Следующим действием выбрать «Доставлена».
   При несовпадении партии выбрать «Расхождение» и написать причину.
   После фактического устранения расхождения можно принять партию снова.
10. Выбрать «Бухгалтер», открыть «Отчёты». Выбрать «Отгруженные»,
    период с сегодняшней датой и код клиента 2. В отчёте будут 3 единицы
    на сумму 45. Для закупок выбрать «Закупленные» и код поставщика 1:
    два прихода с общим количеством 10 и стоимостью 100.

ДОПОЛНИТЕЛЬНЫЕ ВОЗМОЖНОСТИ

Правильный порядок прихода: сверка фактической поставки кладовщиком →
оформление приходной накладной бухгалтером → оприходование и остатки.
В одной накладной объединяются все сверенные позиции выбранной закупки,
которые ещё ожидают оформления. Можно сверить несколько товаров подряд.
Последующие поставки по той же закупке получают следующие номера:
например, 1/1 и 1/2 — первая и вторая накладные закупки № 1.
Если новых позиций нет, кнопка «Накладная» повторно экспортирует последнюю
оформленную накладную; количество на складе не меняется.
Отмена подтверждения не оформляет документ. Отмена сохранения файла
после подтверждения не отменяет уже оформленную накладную и приход.
Счёт поставщика остаётся на весь заказанный состав, приходная накладная —
только на фактически сверенные позиции очередного прихода.
Количество в Received включает и ожидающие накладную позиции, поэтому
повторная сверка не позволяет принять больше заказанного количества.
До накладной эти позиции не доступны для отгрузки и не входят в отчёты
о движениях или стоимость склада. После оформления в отчёте используется
дата фактического поступления, а в накладной — дата её оформления.

Поиск заказов: ввести часть имени клиента, название товара, номер,
состояние или дату в формате дд.мм.гггг. Можно найти заказ без номера.
Состав доступен менеджерам, кладовщику и бухгалтеру в их списках документов;
изменение — соответствующему менеджеру, пока это разрешено правилами склада.
После изменения состава счёт и накладную нужно оформить заново.
Уменьшить сумму ниже уже оплаченной нельзя: возврат денег не реализован.

В карточке товара указывается код конечной категории из дерева.
Нельзя отнести товар к промежуточному узлу или создать цикл категорий.
В категории хранится ответственный кладовщик; при приёмке он предлагается
по умолчанию, а фактический ответственный сохраняется в самой партии.

Для товара с ограниченным хранением при приёмке нужно указать фактическое
«Годен до». Дата не вычисляется из даты поступления: товар мог быть
произведён раньше. Истёкший срок выделяется розовым в остатках.
Автоматического запрета отгрузки просроченных товаров нет: исходное
задание требует выделения, но не задаёт правил списания и запрета.
Товары расходуются по FIFO — сначала более ранняя поставка.

Контрагента без документов можно удалить. Если документы уже есть,
кнопка удаления переводит его в архив. История остаётся доступной.
Товары и категории не удаляются; их карточки можно редактировать.

«Потребность» показывает остатки до 5 единиц, а также нехватку на
неотгруженные заказы. Порог 5 — простое проектное решение;
его можно поменять в методе Reload файла Program.cs.

Отчёт строится по фактическому приходу или расходу, а не по обещанным
количествам. Фильтры: период, код поставщика/клиента и страна происхождения.
Есть строки операций, итоги по товару и общая стоимость.
Общие количества суммируются отдельно по единицам измерения:
килограммы и штуки не складываются в одно число.
Word сохраняется в настоящем формате DOCX. Excel — в XML Spreadsheet 2003,
который открывается через «Файл → Открыть» в Excel. Это не XLSX;
переименовывать расширение не нужно. Ячейки Excel записываются как текст
для сохранения отображения; формулы в экспортированном отчёте не создаются.
Документы — учебные формы, а не утверждённые бухгалтерские бланки.

СОВМЕСТНАЯ РАБОТА И ГРАНИЦЫ ПРОЕКТА

Можно запустить несколько экземпляров с одной папкой данных, в том числе
с доступной всем сотрудникам сетевой папкой Windows:
dotnet run --project Warehouse.csproj -- "\\server\share\warehouse"
У всех пользователей должны быть права чтения и записи в эту папку.
Для проверки на одном компьютере выполните команду запуска в двух терминалах.
Перед действием нажимайте «Обновить». Если коллега уже сохранил изменения,
программа не перезапишет их и предложит обновление. Черновик нужно ввести
повторно. Автоматической синхронизации таблиц и отдельного сервера нет.
Блокировка действует на время одной операции. Проверки и изменения
выполняются до замены файла; при ошибке старые данные сохраняются.
Сетевой режим зависит от поддержки файловых блокировок общей папкой;
облачные папки с синхронизацией не заменяют общую сетевую папку.

Роли выбираются вручную. Это демонстрация рабочих мест, не система
авторизации: паролей и ограничения чтения чужих данных нет.
Платежи вводятся сотрудником после их проведения, банковской интеграции нет.
Курьер фиксирует результат, приложение не выполняет физическую доставку.
Частичная приёмка поддерживается, частичная отгрузка — нет.
Возвраты, отмена оплаченных заказов и списания требуют отдельных правил
и не включены, как и было оговорено в первом этапе.

GIT И СДАЧА

По гайду начиная со второго этапа требуется контроль версий и ссылка
на репозиторий. Локальный репозиторий создан в папке проекта.
Проверить состояние: git status
После собственных изменений: git add . и git commit -m "Описание изменения"
Если Git запросит имя и почту, укажите свои через git config user.name
и git config user.email в этом репозитории.
Создайте пустой репозиторий в своём GitHub/GitLab, затем выполните:
git remote add origin АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ
git push -u origin HEAD
При отсутствии первого коммита перед push выполните git add . и git commit.
Преподавателю передаётся ссылка на этот репозиторий. Публикация в аккаунте
не выполнялась. Данные склада и результаты сборки исключены .gitignore.

ПРОВЕРКА ПОДГОТОВЛЕННОЙ ВЕРСИИ

После исправления порядка приёмки проверены:
— отказ оформления приходной накладной до сверки;
— сохранение сверенных позиций после перезапуска без изменения остатков;
— невозможность отгрузить товар, ещё ожидающий приходную накладную;
— частичное и полное оприходование после оформления бухгалтером;
— количества и суммы отдельных накладных при частичных поставках;
— отсутствие повторного прихода при открытии готовой накладной;
— запрет приёмки сверх заказанного количества, включая ожидающие позиции;
— сохранение состава накладной после последующей отгрузки товара;
— защита от одновременного повторного оформления и создание главного окна.
Проверка выполнена на отдельной Release-сборке: старая запущенная программа
блокировала замену Debug-файла. Перед новым запуском закройте старое окно.

В исходной версии временной проверкой вне проекта выполнены оплата,
отказ отгрузки без оплаты, отгрузка, запрет повторной отгрузки,
отказ при нехватке, доставка, повторная загрузка JSON, конфликт версий,
контроль наличия срока годности, запись DOCX/XML и создание главного окна.
Файлы этой проверки в проект не входят. Полный ручной проход по кнопкам
и открытие экспортов в установленном Office этой проверкой не заменяются.
